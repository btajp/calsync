# デスクトップアプリ 予定詳細のアプリ内表示 設計書

作成日: 2026-07-24
ステータス: 承認済みドラフト(実装の入力)
前提: 統合カレンダービュー(2026-07-21)・トレイ/ポップオーバー(2026-07-23)の上に積む。

## 1. 目的

予定クリック時にブラウザの Google/Outlook カレンダーへ飛ばすのではなく、**アプリ内で詳細を表示**し、そこから **Web 会議に参加**できるようにする。カレンダータブとメニューバーのポップオーバーの両方が対象。

## 2. データ

- `GET /api/events` の各イベントに `description`(プレーンテキスト。Graph は Prefer text / Google は HTML 除去済み — 既存 `DigestEntry.Description` の写像)を追加する。他のフィールドは既存のまま(meeting_url / html_link は実装済み)
- 場所(location)フィールドは NormalizedEvent に存在しないため対象外

## 3. UI

### 3.1 共通の詳細表示部品(`EventDetail`)

- 表示: タイトル / 日時(終日は「終日」・複数日は範囲)/ アカウント(色チップ+id。dedupe 統合された場合は全 account_ids)/ 説明文(改行保持・URL は自動リンク化し https のみ既定ブラウザで開く)
- URL の抽出規則(2026-07-28 レビュー反映): URL は RFC 3986 の構成文字で終端する(`[^\s]+` は日本語説明文で URL 直後の地の文を丸ごと取り込むため不可)。末尾の半角約物(`. , ; : ! ? '`)はトリムし、閉じ丸括弧は URL 内で対応が取れている場合のみ残す。**https として開けない link セグメント(http・パース不能)は text に降格し、クリックできない要素にリンクの見た目を与えない**(会議ボタンが http のとき非表示になるのと同じ方針)
- アクション: **「会議に参加」ボタン**(meeting_url があるときのみ。https 検証つきで既定ブラウザ/会議アプリへ)・「カレンダーで開く」リンク(html_link。従来動作の退避先)・閉じる
- 参加ボタンのサービス表示(2026-07-28 実機フィードバック反映): 会議 URL のホストから Zoom / Meet / Teams / Webex を判定する純関数 `meetingService`(urlSafety.ts)を使い、詳細ビューは「Zoom で参加」等のサービス名+ブランド近似色ドット、ポップオーバー行は色ドット+ツールチップで示す。**ロゴ画像は商標のため同梱しない**(公開リポジトリ)。判定不能は従来の「会議に参加」/「参加」
- Zoom 直接起動(2026-07-28 実機フィードバック反映): 参加ボタン(ポップオーバー行の「参加」含む)は Zoom の会議 URL(`https://<host>/j/<confno>` で host が zoom.us / *.zoom.us / zoomgov.com / *.zoomgov.com)を純関数 `zoomAppUrl` で `zoommtg://<host>/join?action=join&confno=...&pwd=...` へ変換して開く。開けない(Zoom 未インストール等)場合は元の https URL をブラウザで開くフォールバック。変換できない URL(パーソナルリンク /my/ 等)は従来どおりブラウザ。`plugins.shell.open` のスコープを `https://` + `zoommtg://` に限定するカスタム regex を設定(既定 regex は zoommtg を拒否するため必須。副作用として http/mailto/tel が閉じるが TS 側はもともと https のみ)
- レイアウト(2026-07-28 実機フィードバック反映): 「会議に参加」はタイトル右側に置き、説明文だけを内部スクロールにする(タイトル・日時・下部のボタン行は常に見える)。長い説明文(Zoom 招待の定型文等)でボタンが埋まらないようにするため
- 実装は 1 コンポーネントをカレンダービューとポップオーバーで共用(ビルド成果物は同一)

### 3.2 カレンダータブ

- イベントクリック → モーダル(オーバーレイ)で EventDetail を表示。背景クリック / ✕ / Esc で閉じる
- 背景クリックの閉じ判定は「mousedown と click の両方がオーバーレイ自身」のときのみ(2026-07-28 レビュー反映)。click は mousedown/mouseup ターゲットの共通祖先で発火するため、説明文のテキスト選択ドラッグがモーダル外で終わっただけで閉じてしまうのを防ぐ
- FullCalendar へは `toFullCalendarEvents` の extendedProps に EventOut 全体を持たせて受け渡す

### 3.3 ポップオーバー

- スケジュール項目クリック → パネル内で詳細ビューに切り替え(「← 戻る」でリストへ)。ポップオーバーの blur→hide 挙動は不変
- パネルは show/hide で使い回され React state が残るため、blur(hide 直前)で詳細ビューを必ずリストへ戻す(2026-07-28 レビュー反映。戻さないと「会議に参加」でブラウザへフォーカスが移った後、次にトレイから開いたとき古い詳細のスナップショットが表示され続ける)
- 表示のたび(focus)にスケジュールリストを「現在時刻の位置」= 今日の最初の時刻あり項目(終了済みは除外済みなので開催中または次の予定)へ自動スクロールする(2026-07-28 実機フィードバック反映。純関数 `scheduleAnchor` が対象を決め、今日に時刻あり項目が無ければ先頭のまま。3分ごとの定期更新ではスクロールしない — 閲覧中に位置が飛ばないように)
- リスト各行に「参加」ボタンを置き、会議 URL(https)がある予定は詳細を開かずに参加できる(2026-07-28 実機フィードバック反映。表示条件は EventDetail の会議ボタンと同じ isHttpsUrl。行クリック(詳細遷移)とは stopPropagation で分離)
- `ScheduleItem` に元の EventOut への参照を持たせる

## 4. テスト

- Go: events レスポンスに description が載る回帰テスト
- Front: 説明文のリンク化(`linkifyDescription` 純関数: URL 分割・https 判定)・EventDetail の表示条件(会議ボタン有無・終日/範囲表示)・ScheduleItem の参照持ち回りを vitest
- 実機: リリース後確認(クリック動線・会議参加)

## 5. スコープ外

- 参加/欠席の返信・予定編集・出席者一覧・場所表示・リマインダー
